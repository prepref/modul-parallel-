# modul-parallel-

## Описание

Этот репозиторий содержит простой скрипт `create_bots.py`, который **параллельно запускает несколько Telegram-ботов** (по одному токену на «канал работы») и **постоянно опрашивает Telegram API методом `getUpdates`** (long polling).

Скрипт предназначен для отладки/наблюдения: он печатает в консоль информацию о входящих сообщениях (кто написал, в каком чате, текст, время).

## Как это работает (в двух словах)

- **На каждый токен** создаётся экземпляр `WorkChannel`.
- Для каждого `WorkChannel` запускается бесконечный цикл `process_channel(...)`.
- В цикле выполняется long polling через `get_updates(...)` с `offset`, чтобы не получать уже обработанные обновления повторно.
- Все каналы обрабатываются **параллельно** через `asyncio.gather(...)`.

## Требования

- **Python 3.10+** (рекомендуется 3.11+)
- Библиотека **python-telegram-bot** (ветка 20+; используется `ApplicationBuilder` и async API)

Установка зависимости (пример):

```bash
python -m venv .venv
source .venv/bin/activate
pip install -U pip
pip install python-telegram-bot
```

## Подготовка токенов (важно)

Токены ботов **не должны быть захардкожены в коде** и тем более коммититься в git.

Скрипт читает токены из переменной окружения **`BOT_TOKENS`**.

### Получение токена

1. Откройте в Telegram бота **@BotFather**.
2. Выполните команду `/newbot`.
3. BotFather выдаст токен вида `123456789:AA...`.

### Установка `BOT_TOKENS`

Формат:
- токены разделяются **запятой** и/или **переводом строки**;
- пробелы вокруг токенов игнорируются.

Пример (bash):

```bash
export BOT_TOKENS="123456:AAA..., 789012:BBB..."
```

или многострочно:

```bash
export BOT_TOKENS="
123456:AAA...
789012:BBB...
"
```

- `Запускаю обработку N каналов параллельно`

## Что именно логируется

При получении сообщения выводится:

- username/имя отправителя
- `chat_id` и тип чата (private/group/supergroup/channel)
- текст сообщения (или `(без текста)`)
- дата/время сообщения (как отдаёт Telegram API)

## Типовые проблемы и решения

### 1) `RuntimeError: Не найдены токены ботов...`

- **Причина**: не задана переменная `BOT_TOKENS`.
- **Решение**: экспортируйте `BOT_TOKENS` перед запуском (см. раздел выше).

### 2) Ошибка `Conflict: terminated by other getUpdates request` (HTTP 409)

- **Причина**: этот же бот уже где-то запущен в режиме polling (`getUpdates`), и Telegram не позволяет иметь несколько параллельных polling-сессий для одного токена.
- **Решение**: остановите другие процессы/сервисы, которые используют этот токен. Либо переключитесь на webhook-модель (в этом проекте не реализовано).

### 3) «Сообщения не приходят»

Проверьте:
- вы действительно пишете **именно этому боту** (или добавили его в группу);
- бот не заблокирован пользователем;
- у токена нет конфликта polling (см. пункт про 409);
- сеть/файрвол не блокирует исходящие запросы к `api.telegram.org`.

### 4) Flood/Rate limits

Если токенов много, polling может упираться в лимиты Telegram.

- **Рекомендация**: не делайте слишком маленький `timeout` в `process_channel(...)` и не запускайте десятки/сотни ботов без необходимости.

## Безопасность

- **Никогда не коммитьте токены** в репозиторий.
- Если токен уже «утёк» — **сразу перевыпустите** его через @BotFather (`/revoke`) и обновите переменные окружения.
